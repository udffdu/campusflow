# ADR-0001：项目命名、单仓库和服务边界

日期：2026-10-22。状态：仓库结构可实施；服务部署方案待组内评审。

## 背景与已确认信息

6 人团队，模块已经划分，dianashiba 负责 M2 和 D。使用 GitHub 组织 udffdu；用户允许公开课程代码。
技术讨论采用 Spring Boot、Vue 3、PostgreSQL。华为云服务器尚未申请，先完成必做项。

## 本次仓库组织决定

项目名 CampusFlow，中文为校园资源协同平台，仓库名 campusflow。
采用单仓库，独立保存 web、D、M1、M2、M3 目录，以及契约、需求、决策、部署和流水线。
课程 Lab 与个人分析材料保留在项目仓库之外。只初始化结构，不生成未经评审的业务代码。

## 候选与权衡

| 方案 | 收益 | 成本 |
| --- | --- | --- |
| 单应用 | 事务、运行和部署简单 | 需要额外设计网络集成演示；多人边界需约束 |
| 单仓库、少量服务、整套发布 | 契约、模块分工、版本和网络集成清晰 | 增加失败恢复、服务认证和内存成本 |
| 多仓库、独立发布 | 模块自治 | 接口版本与跨仓库发布协调更复杂 |

建议四个后端服务加一个前端，M1/M2/M3 网络集成，D 暂按独立服务预留目录。
PostgreSQL 可共用实例，模块 schema、账号和迁移独立，不跨模块访问业务表。
Docker Compose 为部署候选，不引入 Kubernetes、消息集群或通用审批引擎。

## 待确认及责任

- M1/M3 负责人、D 备用评审人、前端外壳与交付负责人。
- 服务数和资源预算，框架具体版本与兼容性。
- 接口责任与审批冲突策略由受影响模块共同确认。
- 记录每位参与人的意见、分歧和最终确认，不将本 ADR 草案视为已经达成全组一致。
