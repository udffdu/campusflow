# ADR-0003：M2 审批与占用恢复

日期：2026-11-02。状态：实现建议，待用户验收与 M1/D 接口评审。

选择独立 Spring Boot rooms 服务、PostgreSQL m2 schema 和独立数据库账号。保留 D 的统一 Cookie 会话，通过 HTTP 实时授权，不复制用户库；M2 自己判断申请资格、节点和院系范围。

采用固定两级审批，保存节点快照。此时通用流程引擎会增加流程版本、运维与权限模型成本，未带来当前必做项需要的能力；以后节点变动可演进规则版本。审批意见与历史只追加，关键变更以版本号防止旧页面重复操作。

占用不做跨库事务。最终通过只生成 PROCESSING，申请行本身保存持久化待执行操作、递增 operationVersion 和下一次尝试时间。M1 是占用的唯一所有者；若把 M2 表中的批准直接作为“空闲已锁定”，会漏掉个人预约并发。本地行锁、短超时网络调用和 M1 幂等回执组成可恢复流程。吞吐目标是课程规模；高负载时可改为带租约的领取机制，但不能丢失取消与操作版本约束。

通知/审计使用 M2 outbox。每条业务历史对应稳定事件，不依赖事务提交后的临时内存回调。D 收到请求但响应丢失时重复发送同一 eventId，D 去重。测试注入 outbox 插入失败，确认申请与历史也回滚；注入远程失败，确认业务记录保持且事件可重试。

前端沿用已有 Vue 外壳及组件，增加我的申请、审批待办、管理恢复、详情时间线。页面公开 PROCESSING/RELEASING，避免用户把“已点击同意/撤销”误认为资源已经占用/释放。时间输入和显示固定 Asia/Shanghai，不受浏览器时区影响。

M1 真实接口尚不存在；只新增 M2 调用端和契约，不在 M2 内复制 M1 占用模型。演示默认也不伪造批准。生产联调、迁移顺序、故障责任和维修影响需负责人共同评审。

实现参考：[PostgreSQL 行锁说明](https://www.postgresql.org/docs/17/explicit-locking.html)。外部文档仅作为技术参考，不构成项目需求或授权。
