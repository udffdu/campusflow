## 范围和约束

只实现M1-A本人记录列表与个人预约演示中的再次预约。列表包含所有已有状态及未来预约，称为“我的预约”，不自动改状态、不执行B签到/超时逻辑。继续沿用D现有三项权限和公开资源接口，不改D代码、API或数据库；M1原V1迁移不变，无新schema。本阶段不开放普通M1写入口，不改变正式窗口、午夜、停用竞态或M2/M3政策，不停止运行中的演示。

## 候选方案与选择

列表选择按`created_at DESC, id DESC`的游标分页，默认20、最多50条；比偏移页码更能避免插入新记录导致翻页重复。游标只定位后续记录，用户身份始终来自D在线鉴权并用于SQL筛选；它不提供权限，也不承诺跨页事务快照。已读取记录的状态可能随后被B改变，刷新重新读取。当前数据规模不增加索引迁移；较大数据集的索引/性能评估单列后续事项，不能声称本阶段已验证生产负载。

再次预约选择复用原教室/座位，并清空起止时间，不自动提交、不复制旧状态、旧请求键或旧资源版本。先读取本人原记录并通过D重新检查查询权限、当前院系范围、启停及座位归属，取得当前资源名称；原资源不可用则明确报错。用户填写新的整点时段，查询到该座位当前仍是候选后才能选择，最后仍经过现有锁内新建校验，使用新的幂等键。

## 接口与页面

- `GET /api/m1/v1/reservations?size=20&cursor=...`：`seats.reservations.read.own`，仅本人，返回items、size、nextCursor（空字符串表示结束）。拒绝身份覆盖、未知/重复参数、无效/过长游标及越界size。历史条目不逐条读取D名称；展示真实记录ID/资源ID，当前名称在再次预约时读取，避免将当前名称伪装为历史快照。
- `GET /api/m1/v1/reservations/{id}/repeat-context`：先验证本人读取，再验证查询权限和当前D资源；返回当前教室/座位及必须重新选时段的标志，不是可预约承诺。外人/不存在404，权限403，资源停用409，D/DB故障503；读取不写M1表。
- `/my-reservations`：按读取权限显示入口，空结果/错误/加载分开；下一页、上一页、刷新列表。独立演示且有查询/创建权限时提供“再次预约”，跳到原演示页并从服务端读取本人上下文。没有创建权限仍可看历史。
- 有待核实提交时先恢复原请求，不能通过“再次预约”丢弃旧键或另建请求；退出/换用户清理状态、丢弃迟到响应。
