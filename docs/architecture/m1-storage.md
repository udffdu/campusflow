# M1 预约存储：本轮范围与验收

日期：2026-10-28。基于用户选择的并发方案B及五种状态，实现M1内部存储；不改D/M2/M3契约或其schema。B交接按用户授权延后。

## 模型与事务

M1单独拥有m1 schema及Flyway迁移历史。V1包含reservations、reservation_requests、outbox_events三表：预约、按用户/创建操作隔离的幂等请求、待发送事件。无跨模块外键或D业务表读取。资源/用户ID由未来鉴权及主数据适配层校验；本轮存储入口是内部Java调用，不是已授权的HTTP API。

预约记录保存userId、roomId、seatId、起止时刻、五种状态、M1来源、资源版本及本地版本。个人预约事实自身参与冲突判断，不复制另一份可独立修改的可用布尔值。

一次创建：开始独立READ COMMITTED事务→设置本事务锁等待上限→按稳定全序取得用户和教室事务锁→检查幂等记录→校验时间及当前有效预约冲突→写预约/请求/待发事件→提交。响应丢失后相同用户、相同键、相同请求仍返回同一预约，即使开始时刻已过去；未来应用层仍须每次校验身份。

幂等摘要包含用户、教室、座位、起止时刻；resourceVersion为从D读取的元数据，不是用户意图，不将其变化误认为用户改变请求。键按用户隔离；相同键不同意图拒绝。重放返回同一记录的当前状态，不承诺永久冻结首次响应。

锁键由固定M1命名空间和UUID产生稳定64位摘要，排序去重后依次取得。摘要碰撞只会增加等待，不绕过冲突检查。事务结束释放锁；等待超时/死锁报告暂时不可用，不能当作成功。所有未来签到/释放/M2/M3写入必须加入同一协议。

## 验收计划

- 空库迁移、重复执行无新增迁移且原数据保留；SQL约束拒绝非法区间/状态。
- 成功创建三类记录；请求重放只保留一份，载荷冲突拒绝，其他用户相同键独立。
- 预约/用户重叠拒绝，相邻换座允许；终结状态不再作为有效个人占用。
- 独立连接同时抢同座位、同用户跨教室或同幂等键，结果符合互斥和重放规则。
- 独立连接持有教室锁时创建应超时并无写入；删除锁获取后对应测试应失败。
- 用数据库故障触发器让事件写入失败，验证预约和请求记录一起回滚。

测试仅启动独立临时PostgreSQL，不连接用户运行的D演示。M2/M3外部来源表/接口、资源变更跨库竞态、鉴权、开放时间及HTTP仍为后续任务，不能把本轮结果当作完整预约服务验收。
