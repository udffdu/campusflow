# 普通应用个人预约入口方案

2026-10-29。用户要求先完成“正式预约功能”，将跨模块接口确认和联调留待后续；本轮据此实现普通M1应用中的个人预约入口，不再以M2/M3评审为该独立工作前置条件。不是部署授权，也不表示全系统预约完整可用。用户另明确选择自然日窗口：今天可预约明天内开始的时段，后天00:00开始拒绝；参数仍可配置，结束时间继续遵守整点、开放和时长约束。

## 本轮实现与验收

- 普通生产jar可在显式启用并提供可信Origin、独立CSRF秘密、D/数据库/时间参数后装配GET令牌与POST预约，无需test-classpath或DemoFixtureConfiguration。默认关闭写入，缺少/不合法配置启用失败，不通过测试标志偷偷开放。
- 共享已有创建事务/锁/在线D鉴权/幂等/最终时钟及恢复行为，不复制一份预约业务。保留独立旧演示入口兼容；不重启既有演示或读取凭据。
- CSRF仍绑定会话并校验Origin/请求来源；普通应用允许配置HTTPS站点，HTTP仅回环开发；拒绝通配Origin和与服务凭据复用秘密。普通配置和fixture演示不能同时装配两个写入口。
- 正常页面`/seat-reservations`与导航称“座位预约”，确认/提交/保存使用正常个人预约文案；旧`/seat-reservation-demo`保留演示文案。历史复用根据当前环境跳到适当入口，未知请求仍先恢复原键。
- 能力接口明确PERSONAL（普通）、PERSONAL_DEMO（旧fixture）和CANDIDATE_ONLY；普通返回canCreateReservation，而非依靠canCreateDemoReservation。全组集成未完成，productionReady仍false；整室申请/维修未检查的覆盖范围继续显示，不用删除提示制造完整交付。
- 新增可配置CALENDAR_DAYS窗口，生产配置默认该模式，原构造器/旧演示显式ROLLING以保留原验证。自然日计算固定Asia/Shanghai，天数从整日maxAdvance派生；非整日配置拒绝启动。查询和创建同一策略，无前端独立授权逻辑。
- 不改D契约/源码和M1既有迁移，不实现M2/M3流程/来源表或B状态任务。D停用在途竞态、D跨午夜开放表示和生命周期/通知仍列后续，不能谎称已解决。

验证包含模式/天数边界、上海跨日、无权限/归属/CSRF/Origin、正常jar实际创建/恢复/历史/并发及DB故障、关闭模式回归。用正常`java -jar`连独立临时PG和真实D验证，不把测试配置装配冒充普通应用；独立数据库测试辅助类不得进jar。测试和用户验收后提交；不推送、PR或部署。提供复验脚本与另端口预览，密码由用户终端设置。
