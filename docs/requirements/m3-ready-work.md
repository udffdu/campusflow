# M3 当前可推进工作清单

本文是工作计划，不表示功能已经完成。依据本地 D 接口与代码、跨模块契约及 [M3 需求草案](m3.md)；未核验远程最新版本。业务规则仍需双方评审，不能将建议直接标记为已确认。

## 1. 责任与当前边界

- 你：故障上报、本人/管理查询、管理员派单，以及对应页面、测试和过程证据。
- 同学：维修、超时升级、完工、验收评价与 M1 维修限制联动，具体分工由双方确认。
- D 已提供会话授权框架、空间主数据、通知与审计；尚缺 M3 权限映射和维修人员资格接口。
- M1 维修限制接口仍是讨论稿。上报和派单本身不应触发维修下架，按当前任务书链路由进入维修中触发。

## 3. 同学可并行推进的模块内部能力

在共同确认状态机后，可实现维修/完工/验收状态逻辑、评价规则、超时扫描及升级去重、outbox worker 和恢复测试。M1 客户端可先按双方评审的契约设计。

尚无 M1 时不能宣称“维修已真实下架座位”或“验收已真实恢复”；尚无维修人员业务权限时也不能绕过授权运行真实维修操作。

## 4. 建议实施顺序

1. 两人评审需求、状态和数据；向 D/M1 提交 [依赖补充清单](m3-dependencies-and-followup.md)。
2. 建立最小 M3 工程、迁移及可信外部客户端边界，先出方案再实现。
3. 你实现上报/查询，随后实现派单状态与并发；同学并行实现后续状态逻辑。
4. 接页面、测试与 outbox；使用明确的测试替身验证故障行为，不伪装真实集成。
5. D/M1 就绪后按第二份清单完成真实授权、人员资格和网络联动验收。

## 5. 当前不能标记为完成的事项

- 仅用公共层权限成功调用 D，不等于 M3 业务权限验收通过。
- 人工输入某个用户 ID 或测试替身返回合格，不等于实际维修人员资格验证完成。
- 内存状态、HTTP 200、静态页面不能替代持久化、权限和副作用验证。
- 本地业务测试或契约测试通过，不等于与 D/M1 的真实集成通过。
- 文档/配置存在，不等于整套自动部署、生产审批发布或回退已验证。

需求与任务依赖、架构和迁移、首轮真实可运行部分、关键测试及一次破坏实现验证、AI 方案评估和人工验收记录、PR/提交历史、依赖缺口及下一步计划。明确指出演示中哪些使用真实 D、哪些使用测试替身。

本轮不开发自然语言附加 Agent。后续完整交付仍须覆盖维修、超时、验收评价、集成、自动迁移、发布回退和个人伦理报告。
