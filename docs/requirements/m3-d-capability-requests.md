## 4. D-M3-03：维修候选人员查询

请提供仅供服务端调用的正式 HTTP 契约和实现。浏览器不直接访问 D 内部接口，也不复用管理员全量用户列表。

M3 适配请求：

| 字段 | 含义及来源 |
| --- | --- |
| actorId | 已经 D 验证的操作者 ID，由 M3 服务端确定 |
| roomId / departmentId | 从已获权工单读取的真实房间和院系 |
| query | 人员搜索词；M3 当前最多100个 Unicode 码点 |
| page / size | 从0开始分页；当前 page 为0–100000，size 为1–100 |

M3 所需响应示意（占位值不是可执行测试数据）：

```json
{
  "items": [{
    "id": "<人员UUID>",
    "displayName": "<允许展示的名称>",
    "active": true,
    "qualification": "maintenance.repair",
    "globalScope": false,
    "departmentIds": ["<院系UUID>"]
  }],
  "page": 0,
  "size": 20,
  "total": 1
}
```

字段要求：

- id 为真实人员 UUID；displayName 为最少显示信息。
- active 必须为 true，qualification 表示当前有效维修资格。
- globalScope 表示明确的全局服务资格；否则 departmentIds 必须覆盖目标工单院系。若 D 需要更细的房间服务模型，先共同调整契约。
- 只返回符合目标范围及搜索条件的完整候选集合；total 是过滤后的准确总数，不能仅返回前 N 人冒充全部。
- M3 当前约定按显示名、ID 稳定排序，正常分页填满至最后一页；目录并发变更时的不一致/重试语义请确认。
- 真正无候选返回成功且 items=[]、total=0。请求页超出最后一页时items=[]，total仍是过滤后真实总数，不能强制改成0；当前M3要求items长度为min(size,max(0,total-page*size))。权限失败或依赖故障不能伪装为空列表。
- displayName必须非空白；departmentIds必须是数组（明确全局资格时可为空数组），不能缺失/null。当前M3要求qualification精确为maintenance.repair；D若使用其他角色/资格编码，先确认映射，由M3 HTTP适配器转换，不能要求D无评审地照搬Java DTO。搜索词传给适配口前去首尾空白，具体匹配方式及排序规则需D回填。
- 禁止暴露密码、哈希、令牌、会话、密钥或无关个人信息。

D 须确认内部服务认证、操作者上下文校验方式、HTTP 方法/路径、参数限制及错误响应。actorId 不能被当作浏览器可自报的身份证明；若需要额外会话上下文，双方更新适配器。

验收：真实多页候选无静默遗漏；搜索和 total 一致；停用、无资格、越服务范围人员不出现；未授权调用被拒绝；故障返回可识别错误。详细适配提案见 [候选契约](../../contracts/m3-candidate-port.md)，其中阶段说明不替代本文当前状态。

## 5. D-M3-04：提交时的维修资格复核

候选选择不等于最终资格承诺。M3 在新派单提交时调用独立复核，不能以“当前操作者有派单权限”替代“目标人员可以维修”。

请求字段：actorId、assigneeId、roomId、departmentId。actorId 来自已验证会话；assigneeId 是待校验的用户选择；房间/院系来自 M3 工单。

M3 当前要求的结果：

```json
{
  "assigneeId": "<被复核人员UUID>",
  "roomId": "<工单房间UUID>",
  "departmentId": "<工单院系UUID>",
  "allowed": true,
  "reasonCode": null
}
```

- D 校验人员存在、账号启用、有效维修资格及目标服务范围。
- allowed 必须明确为 true 才能放行；响应中的人员、房间和院系必须与请求完全匹配。
- 不合格返回明确拒绝及枚举理由；缺失、畸形响应、认证失败、超时或服务故障不能返回默认允许。
- reasonCode 的取值、HTTP 状态及“业务拒绝/基础设施失败”的区分由 D 提交契约，M3 负责映射页面错误，不透传敏感异常。
- 请共同确认“复核完成后、M3 事务提交前资格被撤销”的竞态语义。当前只是提交前检查，不具备跨服务原子资格快照；如需版本或租约机制，应另行评审，不能宣称已保证。

已成功派单的同操作者、同幂等键、同内容重放：M3仍重新验证操作者当前会话/派单权限及工单范围，但返回已保存的原成功结果，不再次调用目标人员资格复核，也不再次派单。资格变化后的拒绝场景针对尚未成功的新派单；不能把资格撤销后的成功结果重放当作新增越权派单。

验收：选中后停用、撤销资格或调整服务范围，在首次成功派单之前再提交应被拒绝；人员/房间/院系不匹配被拒绝；D 故障时工单、成功历史和派单事件均不新增。M3 自己负责数据库版本并发控制，D 不需要锁 M3 工单。
