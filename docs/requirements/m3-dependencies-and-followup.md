## 2. D 已有能力：复用和配置，不要求重写

- `/internal/v1/authorization`：验证当前操作者会话、权限及可选院系。allowed=false 时不能因响应里带 identity 就放行。
- `/internal/v1/resources` 与 `/{id}`：读取空间有效性/归属。M3 检查 type=ROOM 和 effectiveActive，不直接查 D 数据库。
- 通知接收、去重、回执及站内信：M3 自己保证业务事件先进入本地 outbox；D 不能挽救尚未收到的丢失事件。
- 审计接收与去重：M3 验证业务事实并声明操作者/对象；D 不替 M3 判断派单是否合法。

当前浏览器 `/api/v1/users` 需要 users.manage，不适合作为普通派单管理员的人员候选接口。不能用授予用户管理权限的方式解决人员发现问题。

| 编号 | 补充/确认要求 | M1 最小验收标准 | 到位后 M3 的工作 |

M1-03 的查询接口目前不是已存在事实，属于待讨论方案。不要在 M3 代码中假定接口已上线。上述共同集成需求关联 CF-INT-002/003，避免另建冲突规则。

## 4. 外部补齐后 M3 必须完成的实现

### 你：故障上报、查询与派单

1. 接入真实 M3 权限，取得真实操作者；校验 D 房间有效性及归属，完成上报和查询授权。
2. 接入维修人员候选与派单时资格验证；无资格、越范围、D 不可用均不能错误派单。
3. 在 M3 本地事务内原子写入派单、人员/操作者/时间、版本、历史和 outbox；同键重试去重、同版本并发只成功一次。
4. 完成页面、共享路由/代理接入、CSRF、错误与版本冲突提示；前端权限仅辅助，服务端最终授权。
5. 执行 m3.md 的 R01/R02/R03 全部验收；真实数据库与 D 网络调用补充集成证据。向同学交接稳定的已派单工单。

### 同学：后续维修与完整集成

1. 实现被指派人员开始维修、提交完工、超时升级、验收通过/退回与评价，以及对应业务权限和页面。
2. 接 M1 限制设置/解除；约定待验收期间仍封禁，确认后实现；多工单解除互不干扰。
3. 实现持久化事件发送、超时确认、重试、乱序防护与重启恢复；展示业务状态和同步状态，避免伪装已下架/已恢复。
4. 接 D 通知审计，区分“业务已成功”“事件已接收”“通知已送达”；外部故障不丢业务事件。
5. 完成多工单、M2 共存、已有预约、失败/响应丢失/重启等真实跨模块测试。

## 5. 两人及全组共同交付

- 先评审后实现跨模块契约、公共层及 schema 变更；新增迁移，不手工改库或修改已应用迁移。
- 明确共享前端、CI、整套部署负责人；M3 提供自己的构建/测试/迁移/配置，接入现有 D+web 流程。D/M1 业务补齐不会自动完成部署。
- 测试失败阻断后续阶段与合并，测试环境自动部署全模块，生产人工审批；版本/tag 可追踪，发布与数据库兼容回退分别验证。
- 按需求更新实现和验证路径；尚未做的保持 planned/in_progress，不把依赖提供方完成当作 M3 验收通过。
- 以真实缺陷与权衡记录伦理分析；两人各自保留 AI 方案评估、人工验收、持续提交及交叉评审证据。
