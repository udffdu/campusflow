# CF-M1-010 未签到取消、释放与违约验证记录

日期：2026-10-31。状态：代码、隔离自动检查和页面预览工具已完成；用户已人工确认红色违约历史效果。本文记录本地证据，不代表远程 CI、真实 SMTP、PR、部署或完整 M1 已通过。

## 已实现行为

- 后台按服务端时钟扫描`startAt + 15分钟`已到且仍为`CONFIRMED`的预约；
- 复用预约创建和签到相同的用户/教室事务锁，锁内重读状态和时间；
- 在一个事务中完成`CONFIRMED -> NO_SHOW`、版本递增、转换事实、一次违约和唯一`RESERVATION_NO_SHOW` outbox事实；任一步失败整体回滚；
- `NO_SHOW`不再参与个人占用判断，因此原座位可重新预约；不会删除M2/M3等其他来源限制；
- 重复扫描、并发实例或重启恢复不重复记违约，不重复创建业务通知事实；
- 截止点前签到先成功时保留`CHECKED_IN`；到达或超过截止点的迟到签到先幂等终结为`NO_SHOW`并被拒绝；
- `CHECKED_IN`到预约结束后由同一生命周期任务自动转为`COMPLETED`；
- 未签到通知通过现有D站内信和邮件任务投递，包含教室、座位、预约时间、取消/释放和违约说明；
- “我的预约”以红色边框/背景、图标及“未签到违约”文字共同表达状态，签到成功记录使用绿色并显示服务端签到/完成时间和使用时长。

## 自动检查

```sh
bash scripts/check-m1-no-show.sh
```

脚本先执行D、M1和Web测试及生产构建，再启动隔离PostgreSQL、D、M1和本地模拟SMTP，验证一次完整未签到终结、占用释放、单次违约、站内信与邮件投递。测试使用`DatabaseFixture.makeNoShowDue`推进隔离数据库中的预约时间；该入口只编译到`target/test-classes`，生产jar中不存在。

本轮实现后的本地结果：M1后端195项测试、Web 63项测试、TypeScript检查和Vite生产构建通过；隔离CF-M1-010链路曾输出PASS。上述均为本地结果，远程GitHub Actions以对应提交实际状态为准。

## 人工页面验收

```sh
bash scripts/start-m1-no-show-preview.sh
```

1. 在终端设置至少12字节的临时密码并保持脚本运行。
2. 使用脚本打印的`http://[::1]:5374/my-reservations`，以`student`和该密码登录。
3. 脚本会先经公开预约API创建一条示例预约，再只在本次隔离数据库推进其时间；等待终端显示“红色违约示例已准备完成”。
4. 打开或刷新“我的预约”，应看到红色“未签到违约”，不再显示签到输入框；文字说明预约已取消、座位已释放并记录一次违约。
5. 打开通知中心和`http://127.0.0.1:8025`模拟邮箱，核对教室、座位、上海时间和取消原因。
6. 返回“座位预约”可继续手工创建记录；脚本持续监听每一笔新预约并逐笔推进，终端确认完成后刷新“我的预约”。
7. 按`Ctrl+C`停止；数据库和进程属于本次隔离环境，不要把`tmp/`提交到仓库。

人工预览只加速临时数据，不能替代正式15分钟边界的自动测试，也不能作为真实外部邮箱送达证据。
