# CF-M1-011 预约运营查询与统计验证记录

日期：2026-10-31。状态：代码、隔离自动检查和页面预览工具已完成，用户已人工确认运营看板可正常加载。本文记录本地证据，不代表远程 CI、PR、部署或生产规模性能验证通过。

## 验收范围

- 只有显式获得`seats.operations.read`的有效会话可以进入运营页面和读取接口；该权限不自动授予既有角色；
- 运营人员只能看到其院系下的教室、座位和预约，范围外筛选返回403；
- 支持最长31天的时间区间，以及教室、座位、预约状态筛选；筛选同时作用于明细和统计；
- 返回预约总数、五状态分布、签到率、违约数、预约时长、实际使用时长、预约时段实际利用率及教室/座位排行；
- 分页使用与筛选条件绑定的不透明游标，稳定排序且静态样本中不重不漏；
- 页面显示资源、上海时间、状态、使用时长和预约编号，但不显示学生身份；
- D 不可用时返回503，不退化为无院系约束的查询。

统计定义及错误响应以[运营查询契约](../../contracts/m1-operations-api.md)为准。

## 自动检查

```sh
bash scripts/check-m1-operations.sh
```

脚本依次执行 D 与 M1 测试、Web 测试和生产构建，再启动隔离 PostgreSQL、D、M1，创建仅含运营读取权限的`SEAT_OPERATOR`角色，并验证以下真实 HTTP 场景：

1. 缺少会话返回401；
2. 普通预约用户返回403；
3. 院系范围、已知样本统计及个人信息最小化正确；
4. 不透明游标翻页不重复、不遗漏；
5. 范围外教室筛选返回403；
6. 状态筛选后的列表与汇总一致；
7. D 不可用时返回503。

本轮实现期间，Platform 完整测试、M1 的`QueryHttpTest`与`ReservationOperationsStoreTest`共71项、Web 15个测试文件共70项、TypeScript检查及生产构建曾通过；隔离HTTP脚本输出7项PASS。人工预览发现前端最初错误限制固定主数据UUID的版本位，修复后新增真实院系编号回归用例并单独通过4项`operations.test.ts`测试，用户随后确认页面正常。以上均为本地结果；后续代码变化应重新执行脚本，远程结果以对应提交的 GitHub Actions 为准。

## 人工页面验收

先停止占用相同端口的旧预览，再在仓库根目录执行：

```sh
bash scripts/start-m1-operations-preview.sh
```

1. 按提示设置12～72字节临时密码并保持终端运行。
2. 打开脚本打印的`http://[::1]:5474/seat-operations`，使用账号`operator`及该临时密码登录。
3. 初始样本应显示5条本院系预约，五种状态各1条；另有1条其他院系记录，不应出现在页面。
4. 签到率应为66.7%，违约数应为1；实际使用时长应大于0且小于预约时长。
5. 依次选择教室、座位和状态筛选，确认明细、状态分布、指标和排行同步变化；选择“违约”时应只显示违约记录。
6. 明细应包含教室、座位、时间、状态、使用时长和预约编号，不应出现学生姓名、账号、用户编号或邮箱。
7. 退出`operator`后以普通`student`登录，不应获得运营导航或读取权限。
8. 按`Ctrl+C`停止；数据库、日志和进程属于本次隔离环境，`tmp/`不应提交。

预览脚本只在测试 classpath 中生成五状态样本，不修改正式时间规则、正常开发数据库或生产 jar。需要同时使用多个身份时，应使用不同浏览器、不同浏览器配置，或普通窗口与无痕窗口，避免共享`CF_SESSION` Cookie。
