## 代理与 CSRF 待确认方案

供 D/共享入口负责人评审，尚未修改 Vite/Nginx：

- 同源 /api/v1/maintenance/ 优先进入 M3:8083，保留完整路径、Cookie 和请求头；其余 /api/ 维持 D:8080；/internal/ 继续禁止浏览器入口访问。
- Vite 应使用精确的 M3 前缀规则放在 /api 前；Nginx 使用更长的 /api/v1/maintenance/ location，proxy_pass 不加会重写路径的 URI 后缀。容器服务名由部署负责人确认，不能默认现有 Compose 已包含 M3。
- 写请求每次先 GET /api/v1/maintenance/csrf，仅接受 headerName=X-M3-XSRF-TOKEN，再带 M3 token 和 Idempotency-Key POST。credentials=same-origin；无浏览器服务密钥，不读取 CF_SESSION。
- D 原有 api.ts、CSRF Cookie/缓存/请求头不变。M3 每次提交重新取得自己的令牌，避免跨登录复用前端缓存；生产 Secure Cookie 需要 HTTPS。
